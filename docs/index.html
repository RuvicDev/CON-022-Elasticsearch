¿Qué es y para qué sirve?

El conector Elasticsearch permite que el agente de Ruvic consulte tu clúster en modo solo lectura: puede buscar y contar documentos, pero nunca indexarlos ni modificarlos. Una vez configurado, puedes pedirle al agente cosas como:

  • “Busca los productos de la categoría electrónica y muéstrame los primeros 10.”
  • “¿Cuántos pedidos hay registrados en la ciudad de Bogotá?”
  • “¿Qué índices tiene el clúster y cuántos documentos hay en cada uno?”

Operaciones soportadas:

Operación Qué hace
db.list_indices Lista los índices del clúster con su tamaño y conteo de documentos
db.search Busca documentos en un índice usando Query DSL
db.count Cuenta los documentos que cumplen una consulta
Solo lectura, por diseño El conector nunca llama a index, update, delete ni bulk: solo emite operaciones de búsqueda y conteo. Además, el usuario dedicado solo tiene privilegios de lectura. Hay dos barreras independientes.

Prerrequisitos

  • Un clúster Elasticsearch 8.x (self-hosted, Elastic Cloud, o Docker) con seguridad habilitada (activada por defecto en 8.x).
  • Acceso administrativo al clúster (usuario elastic o un rol con permiso para crear usuarios y roles), solo durante la configuración inicial.
  • Acceso de red desde la plataforma Ruvic al clúster (host y puerto alcanzables; regla de firewall o lista de IPs permitidas si aplica).
  • Los datos de conexión: host y puerto (por defecto 9200).

Configuración en el fabricante

Vas a crear un rol y usuario dedicados de solo lectura para Ruvic. No uses el usuario elastic ni el de tu aplicación: un usuario dedicado permite auditar la actividad del agente y limitar el acceso al mínimo.

  1. Crea el rol de solo lectura.

    Desde Kibana (Stack Management → Roles) o vía API con un usuario administrador:

    POST /_security/role/ruvic_reader
{
  "cluster": ["monitor"],
  "indices": [
    { "names": ["*"], "privileges": ["read", "view_index_metadata"] }
  ]
}
    Nota Ajusta "names" a un patrón específico (ej. ["productos-*"]) si quieres limitar el acceso a ciertos índices en vez de todos.
  2. Crea el usuario y asígnale el rol.

    Elige una contraseña fuerte (mínimo 16 caracteres, generada aleatoriamente) y guárdala: la usarás en el formulario de Ruvic (campo Contraseña):

    POST /_security/user/ruvic_reader
{
  "password": "CAMBIA_ESTA_CONTRASEÑA",
  "roles": ["ruvic_reader"]
}
  3. Habilita el acceso de red desde Ruvic.

    Si tu clúster restringe conexiones por IP (habitual en producción), permite la IP de la plataforma Ruvic:

    • Servidor propio: regla de firewall del sistema operativo para el puerto 9200.
    • Elastic Cloud / servicio administrado: agrega la IP en la lista de tráfico permitido (traffic filter) de la consola del proveedor.
    [ Captura: regla de firewall / traffic filter con la IP de Ruvic — reemplazar por assets/img/elasticsearch-firewall.png ]
  4. Verifica el usuario desde fuera del servidor.

    Desde una máquina distinta al clúster (idealmente con salida de red similar a la de Ruvic):

    curl -u ruvic_reader:TU_CONTRASEÑA https://TU_HOST:9200/_cluster/health

    Si responde con un JSON de estado del clúster, el fabricante quedó listo. Anota estos valores para la siguiente sección: host, puerto, usuario y contraseña.

Permisos requeridos

Principio de mínimo privilegio: el usuario de Ruvic solo necesita estos privilegios. No otorgues all, manage, index, write ni delete.

Privilegio Para qué sirve
monitor (a nivel de clúster) Listar índices y ver su estado (db.list_indices)
read (por índice) Buscar y contar documentos (db.search, db.count)
view_index_metadata (por índice) Consultar el mapeo y la metadata del índice necesaria para ejecutar búsquedas

Configuración en Ruvic

Entra a Settings → Conectores, busca la tarjeta Elasticsearch y pulsa Configurar. Diligencia el formulario con los valores que obtuviste en la sección anterior:

Campo del formulario Valor
Host Hostname o IP del clúster (ej. search.empresa.com)
Puerto 9200 (salvo configuración distinta)
Usuario ruvic_reader
Contraseña La contraseña del paso 2. Se guarda cifrada como secreto: la interfaz no volverá a mostrarla
Usar HTTPS Activado por defecto; la mayoría de clústeres 8.x lo requieren
Verificar certificado TLS Activado por defecto; desactívalo solo en entornos de prueba con certificados autofirmados
Timeout de conexión Opcional; 10 segundos por defecto

Guarda y pulsa Probar conexión — la plataforma se conectará a tu clúster y confirmará que las credenciales y la red funcionan.

[ Captura: formulario del conector Elasticsearch en Settings → Conectores — reemplazar por assets/img/elasticsearch-form.png ]

Verificación

  1. Test de conexión exitoso.

    El botón Probar conexión debe responder: “Conexión exitosa a tu-host:9200”. La tarjeta del conector cambia a estado Configurado.

  2. Automatización mínima de prueba.

    Abre una conversación nueva con el agente y pídele: “Lista los índices del clúster de Elasticsearch y dime cuántos documentos tiene cada uno.” El agente debe responder con el listado real de tus índices. Si lo hace, el conector quedó operativo de punta a punta.

Solución de problemas

Mensaje / síntoma Causa probable y solución
“Autenticación fallida: usuario o contraseña inválidos” Contraseña mal copiada o usuario inexistente. Reintenta el paso 2 de la sección 3 y vuelve a guardar el formulario (deja la contraseña vacía para conservar la anterior o escribe la nueva para reemplazarla).
“No se pudo conectar … (timeout)” La plataforma no alcanza el host/puerto. Revisa el paso 3 (firewall / traffic filter) y que el host no sea localhost (debe ser accesible desde Ruvic, no desde tu equipo).
Error de certificado TLS al conectar El clúster usa un certificado autofirmado. Desactiva "Verificar certificado TLS" en el formulario SOLO si estás en un entorno de prueba controlado; en producción, instala un certificado válido.
El agente lista índices pero “no tiene permiso” al buscar en uno Falta el privilegio read o view_index_metadata sobre ese índice específico en el rol. Repite el paso 1 de la sección 3 ajustando el patrón "names".
El conector aparece “Sin configurar” tras guardar Algún campo obligatorio quedó vacío. Ábrelo de nuevo y completa host, puerto, usuario y contraseña.

Preguntas frecuentes y notas de seguridad

¿El agente puede indexar, modificar o borrar documentos?

No. El conector nunca llama a index, update, delete ni bulk, y el usuario ruvic_reader solo tiene privilegios de lectura (read, view_index_metadata, monitor). Hay dos barreras independientes.

¿Dónde queda guardada la contraseña?

Como secreto en el almacén de credenciales de la plataforma, asociado a tu usuario. La interfaz nunca vuelve a mostrarla; solo indica “definida”. Para cambiarla, escribe una nueva en el formulario; para conservarla al editar otros campos, deja el campo vacío.

Rotación de credenciales

Recomendado cada 90 días o según tu política: cambia la contraseña con POST /_security/user/ruvic_reader/_password, actualízala en el formulario del conector y pulsa Probar conexión.

¿Qué hago si la contraseña se compromete?

  1. Cambia la contraseña de inmediato o deshabilita el usuario (PUT /_security/user/ruvic_reader/_disable).
  2. Revisa los logs de auditoría de seguridad del clúster.
  3. Actualiza la nueva contraseña en el formulario del conector.

¿Expiran las credenciales?

Por defecto no (usuario/contraseña de Elasticsearch no caducan solos). Si tu política exige expiración, gestiónala manualmente rotando la contraseña según tu calendario de seguridad.

Buenas prácticas Usa siempre un usuario dedicado y de solo lectura; restringe el rol a los índices que el agente realmente necesita en vez de "*"; mantén habilitada la verificación de certificados TLS en producción; y evita compartir la contraseña por canales no seguros.
